# Contributing to TalentOS

Thank you for helping build open professional identity and talent discovery infrastructure.

## Before contributing
- Read the product principles and roadmap.
- Check open issues before substantial work.
- Discuss breaking architecture changes before implementation.
- Do not introduce paid services or vendor lock-in without maintainer approval.
- Never include real candidate data, secrets or credentials in commits, fixtures or screenshots.

## Development expectations
- TypeScript with strict type checking.
- Accessible, mobile-first interfaces.
- Server-side authorization for sensitive operations.
- Database changes through reviewed, versioned migrations.
- RLS tests for private and tenant-owned data.
- Unit, integration and end-to-end tests as appropriate.
- Document API and schema changes.
- Preserve portability and provider-neutral boundaries.

## Pull requests
Explain the problem, user impact, technical approach, data/privacy implications, tests run and results. Include screenshots for interface changes. Do not mark mock or placeholder behavior as complete functionality.
